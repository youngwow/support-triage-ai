# Автоматизация обработки тикетов поддержки

Сервис определяет тему и уровень риска обращения, маршрутизирует его и — если тикет того стоит — готовит оператору черновик ответа по базе знаний. **Пользователю не отправляется ничего**: `auto_send_allowed` означает «прошёл бы все проверки», а не «ответ ушёл»; человек остаётся в контуре всегда.

- **Быстрый путь, синхронный** — `POST /api/v1/tickets`: маскирование PII → детерминированные правила → классификация одним структурированным вызовом Gemini → `risk = max(правила, модель)` → маршрут → запись → аудит → постановка в очередь. Ответ 201 содержит решение триажа.
- **Медленный путь, асинхронный** — ограниченная очередь → воркер → граф LangGraph из трёх узлов: `retrieve` по FAISS → `generate` → `escalate`. Черновик обязан опираться на найденные фрагменты регламента, иначе тикет уходит оператору.

6 категорий (`billing/faq`, `billing/payment_issue`, `billing/refund`, `account_recovery`, `technical_issue`, `other`), риск `low` / `medium` / `high`, маршруты `auto_answer` / `operator_queue` / `senior_escalation`.

## Как запустить PoC

Нужны `uv` и Python ≥ 3.14.

```bash
uv sync
uv run pytest -q                      # 289 тестов, ~3 с
uv run python -m src.main             # http://localhost:8000, Swagger на /docs
uv run python scripts/demo.py         # end-to-end демо против запущенного сервиса
uv run python scripts/evaluate.py     # baseline на правилах по golden set, без сети

RUN_INTEGRATION=1 uv run pytest -m integration -q   # проверка ранжирования на реальной модели
```

**Ключ не обязателен.** Без `GEMINI_API_KEY` в `.env` сервис стартует, классификация уходит на запасной классификатор по правилам, и все тикеты маршрутизируются человеку. `WARMUP_ON_STARTUP=false` дополнительно пропускает загрузку 3B-модели эмбеддингов (~50 с и десяток гигабайт весов), черновики деградируют до «оператору отдаются только найденные фрагменты».

```bash
docker compose up --build                          # с GPU
WARMUP_ON_STARTUP=false docker compose up --build  # на хосте без GPU
```

## Какой сценарий демонстрируется

`scripts/demo.py` прогоняет оба пути, которых требует кейс, на реальных фикстурах из `data/tickets/historical_tickets.json`:

| Тикет | Что это | Исход |
| --- | --- | --- |
| **T-1001**, happy path | «как отвязать старую карту и привязать другую» | `billing/faq`, риск `low`, маршрут `auto_answer`, обоснованный черновик со ссылкой на `payment_methods.md`, статус `draft_ready` |
| **T-1004**, рискованный путь | восстановление доступа с почтой и паспортными данными в теле | текст маскирован до `[EMAIL]` / `[PASSPORT]`, риск поднят до `medium`, `auto_send_allowed=false`, статус `awaiting_operator` |

Третья фикстура, **T-1003** (четыре списания и угроза полицией и судом), уходит в `senior_escalation`: она не ставится в очередь черновиков вообще и **не стоит ни одного вызова генерации**.

## Что реализовано, а что архитектурный дизайн

| Реальный код | Целевой дизайн, предложение |
| --- | --- |
| FastAPI и 6 эндпоинтов, маскирование PII, правила, экран prompt injection | Адаптеры каналов: чат, email, веб-форма, мобильное приложение |
| Классификация вызовом Gemini и запасной классификатор на правилах | Дистиллированная компактная модель ради бюджета 500 мс |
| Граф LangGraph, retrieval через FAISS и Giga-Embeddings | Тот же механизм |
| Тикеты и append-only аудит в памяти | PostgreSQL + S3-совместимое хранилище для аудита |
| `asyncio.Queue` на 100 элементов и один воркер | RabbitMQ |
| Метрики как проекция аудита в JSON | Экспортер Prometheus и дашборды Grafana |

## Допущения и ограничения

Три компромисса приняты сознательно, а не по недосмотру:

1. **Бюджет 500 мс на быстром пути не выдержан.** Классификация сделана вызовом LLM.
2. **Очередь недолговечна** — `asyncio.Queue` внутри процесса.
3. **Всё состояние в памяти** — тикеты, журнал аудита, FAISS-индекс.

## Зачем это бизнесу

200k тикетов в день — это ~2.3 rps в среднем и до 33 rps на инцидентном всплеске (10–20k обращений за 10 минут), и SLA по первому ответу ломается именно в такие моменты, на потоке однотипных обращений. Система снимает с операторов две самые механические части работы — определить тему и риск и найти нужный фрагмент регламента: типовые `billing/faq` приходят к оператору уже с черновиком и ссылкой на источник, а спорные списания и подозрения на взлом попадают к `senior_escalation` сразу, а не после двух перекладываний между очередями. Стоимость ограничена архитектурно, а не бюджетным алертом: не больше двух вызовов LLM на тикет, ноль вызовов генерации для высокорисковых, потолок скорости генерации задан размером очереди.
